# 作业 6：输出日历

## 实现思路

程序输入 1900 至 2099 年和 1 至 12 月，输出以星期日开头的月历。以 1900 年 1 月 1 日为星期一，累加整年和整月的天数，并对 7 取余，确定月初位置。闰年按“能被 400 整除，或能被 4 整除且不能被 100 整除”判断。

`MAINCODE` 封装输入和输出，`CALCCODE` 封装天数、星期和闰年计算。两个代码段之间使用 `FAR CALL`，同段内的辅助过程使用近调用。日期按两位右对齐，每满 7 列换行。

## 参数传递的比较

| 方式 | 程序中的使用 | 优点与不足 |
| --- | --- | --- |
| 寄存器 | `READ_NUMBER` 用 `DX`、`BX`、`CX` 和 `SI` 传入提示、范围和最大位数；`IS_LEAP` 用 `AX` 传入年份 | 访问直接，但数量有限，需要约定哪些寄存器由过程保存 |
| 数据段 | `FIRST_DAY` 读取 `YEAR_VALUE` 和 `MONTH_VALUE` | 多个过程共享方便，但依赖全局状态，不适合重入调用 |
| 栈 | `MONTH_LENGTH` 接收年份、月份，返回时用 `RETF 4` 释放参数 | 每次调用有独立参数，便于嵌套，但压栈顺序、偏移和清理方式必须一致 |

过程计算结果统一由 `AX` 返回。输入过程还通过 CF 表示成功或失败。

## 编程中需要注意的问题

远调用比近调用多保存一个 `CS`。先压月份、再压年份，进入远过程并执行 `PUSH BP` 后，年份位于 `[BP+6]`，月份位于 `[BP+8]`。若沿用近调用的参数偏移，就会误把返回地址当成年份。

`FAR CALL` 必须配合 `RETF`，才能同时恢复 `IP` 和 `CS`。`MONTH_LENGTH` 的 `RETF 4` 还会释放两个字参数。若使用普通 `RET`，代码段和栈都会出错。

8086 条件跳转只有 8 位有符号位移，范围为下一条指令起的 −128 至 +127 字节。较远的输入错误分支采用“反转条件，再执行近跳转”：

```asm
JNC YEAR_OK
JMP NEAR PTR INPUT_ERROR
```

这样条件跳转只跨过一条指令，远处的错误处理由 16 位位移到达。

连续读取两行时，DOS 重定向输入可能残留 CRLF 中的 LF。解析第二行前跳过这个前导换行，避免把合法月份识别为非数字。

## 跳转和反汇编体会

| 指令形式 | 典型机器码 | 对 IP、CS 的影响 |
| --- | --- | --- |
| 短跳转 | `EB 位移8`，条件跳转使用相应条件操作码 | 按位移修改 IP，CS 保持不变 |
| 近跳转／近调用 | `E9 位移16`／`E8 位移16` | 段内修改 IP；近调用额外压入返回 IP |
| 远跳转／远调用 | `EA 偏移16 段16`／`9A 偏移16 段16` | 同时修改 IP、CS；远调用压入返回 CS 和 IP |

位移以跳转指令后的地址为基准，多字节数值按小端顺序编码。例如本程序的近跳转 `E9 62 01` 从下一地址 `0024H` 加上 `0162H`，到达 `0186H`。

本次 DEBUG 中，远调用机器码为 `9A 00 00 8B 07`，目标是 `078BH:0000H`。它让 `SP` 减少 4；`RETF 4` 返回后，`SP` 从 `01F8H` 恢复为 `0200H`。段地址随加载位置变化。

C 反汇编使用 Windows x64 调用约定，前四个整数或指针参数放在寄存器中，第五参数放在栈中。`read_number` 展示了两种位置；`first_day` 直接读取全局变量。编译器还把取模改写为乘法、移位和减法，注释需要结合源码理解这些指令。
